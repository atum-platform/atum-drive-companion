# Atum OEM identity build

Build from the complete GPL repository using the official Craft SDK. Pass
`-DOEM_THEME_DIR=<source>/oem/atum -DATUM_DRIVE_PROFILE=s2` for the disposable test
build, or `production` for the separately identified production build. A missing
or unknown profile stops configuration. The test and production applications have
different bundle IDs and credential-store service names. Profiles are compiled
into the binary; no preferences or dynamic registration can replace them.

The client is public, uses random IPv4 loopback redirects with PKCE and state, and
requests only `openid`. Virtual files, automatic updates, crash uploading and HTTP
body logging are off for this build. Enrollment is pinned to its Drive origin,
issuer, client, scope and MAS subject; returned UserInfo must agree with the ID
token before secure-store readiness. Refresh verifies the same subject even when
MAS omits a new ID token. Failure preserves the existing custody fences and files.

Artwork is an original CC0 monogram generated by `artwork/generate.py`. To reproduce
the committed vectors and PNGs, build its small Qt Gui/Svg CMake renderer against
the same SDK and pass the resulting render-icons binary to that Python script.
No upstream trademark artwork is used for these OEM icons. Preserve the repository
GPL notices and publish exact source/build instructions with every distributed
version. This directory alone is not a signed release or full lifecycle acceptance.
